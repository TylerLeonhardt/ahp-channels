01 / Claude Channels · 1:15

  • Start with something familiar: message a bot in Discord or Telegram, and it reaches an agent conversation that is already running.
  • A channel is an MCP server that can push events. Replies are tool calls back through that server, not just text printed in the editor.
  • The plugin also contains setup and access skills. It owns credentials, pairing, and platform behavior.
  • Transition: what if we kept those plugins, but connected them to an AHP session instead?
Reference: Claude Code channels documentation. Channels are a research-preview feature in Claude Code.

02 / Multi-client extensibility · 2:30

  • Read left to right: the existing plugin talks MCP to our daemon. The daemon creates an AHP client for each named channel and attaches it to an existing session.
  • The interesting part is registration: the client contributes proxy tools AND a plugin customization. The host discovers the plugin's skills; they are not MCP tools.
  • Tool calls route back to the owning channel client and its MCP process. We disable the plugin's host-side MCP server to avoid launching a duplicate bot.
  • The VS Code client stays connected to the same session. The channel client adds capabilities without replacing that UI or creating a second conversation.
  • Punchline: a protocol client is not only a chat front end. Multi-client AHP can be an extensibility model.
Implementation: bridge.ts publishes the active client's tools and customizations; plugins.ts creates the plugin contribution.

03 / Try it · 1:15

  • Choose the terminal or the VS Code extension. They manage the same daemon and state directory.
  • The VSIX bundles the bridge runtime, so the extension does not need a separate CLI installation.
  • Install a channel plugin, pick an existing local Agent Host session, and complete the plugin's setup and pairing. A supported host, Git, and the plugin runtime (currently Bun for Discord/Telegram) are prerequisites.
  • Close with the takeaway: new client, new capabilities, same conversation.
Release cue: the npm-distributed VSIX starts with the next npm release containing the extension. The Marketplace link becomes available after the manual Marketplace upload.
